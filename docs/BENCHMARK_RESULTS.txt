1. METHODOLOGY & BENCHMARK ARCHITECTURE
---------------------------------------
In accordance with independent compiler technical audits, NEXUS evaluates
runtime performance using two strictly separated benchmark categories:

  Category A: Raw Native Ahead-Of-Time (AOT) Code Generation
    Measures physical instruction throughput on un-eliminated CPU execution.
    Optimization loops are compiled without recurrence-attractor shortcuts
    (--no-hydron) to measure the raw efficiency of the emitted machine code.

  Category B: Semantic Computation Elimination (Superoptimization)
    Measures program analysis, induction variable scaling, and closed-form
    mathematical resolution (HYDRON Turbines 1–7). This tests the compiler's
    ability to prove loop invariants, verify dynamic fixed-point attractors,
    and eliminate unnecessary computation while guaranteeing exact equivalence.

Test System:
  OS: Linux x86-64 (Direct Kernel Syscalls, 0% libc, 0% ld-linux)
  Compiler Core: compiler/nexc.nex (Self-Hosted NEXUS Machine Code Synthesizer)
  Iterations: 50,000,000 loop steps
  Runs: Best of 3 fresh-process executions


2. CATEGORY A: RAW NATIVE AOT CODE GENERATION (`./nexus bench`)
---------------------------------------------------------------
Evaluates raw machine code execution across 50,000,000 physical loop iterations
without semantic loop shortcuts.

Results (best of 3):
  Un-eliminated 50M loop:          62.48 ms
  Physical instruction throughput: ~800.2M physical-iters/sec
  Emitted binary size:             38,400 bytes
  External runtime dependencies:   0% (Direct Linux ELF64 syscalls)

Breakdown:
  - Loop register promotion keeps induction variable in RAX/RBX.
  - Power-of-2 multiplications emit single-cycle SHL.
  - Truncating integer division emits branchless CQO + SAR sequence.
  - Zero redundant stack memory spills inside inner arithmetic loop.


3. CATEGORY B: SEMANTIC RECURRENCE ELIMINATION (`./nexus hydron`)
-----------------------------------------------------------------
Evaluates the HYDRON Engine (Turbines 1–7) on a non-linear integer recurrence:
  acc(n+1) = floor((acc(n) + n) / 2)

Mathematical Transformation:
  1. The optimizer recognizes the recurrence and performs attractor analysis.
  2. The error term decays exponentially: e(n+1) = floor(e(n) / 2).
  3. Executes a 64-iteration convergence preamble.
  4. Inserts a runtime safety guard validating the fixed-point manifold:
     acc == i - 2
  5. Computes the closed-form mathematical resolution for the remaining iterations.

Results:
  Logical iterations:             50,000,000
  Executed convergence steps:     64
  Final execution time:           0.40 ms
  Computation elimination factor: ~156.7x
  Numerical verification:         100% exact numerical match with unoptimized


4. COMPILER OPTIMIZATION SUBSYSTEMS (HYDRON TURBINES 1–7)
---------------------------------------------------------
Turbine 1: Fast Power-of-2 Multiplication
  Rewrites x * (2^k) into SHL instructions.

Turbine 2: Fast Power-of-2 Truncating Division
  Rewrites x / (2^k) into 4-cycle branchless CQO; AND; ADD; SAR sequence,
  faithfully matching IEEE C99 truncating integer division semantics.

Turbine 3: Redundant Store-Load Forwarding
  Tracks accumulator values across consecutive assignments (hyd_rax_var)
  to eliminate memory reloads from the stack.

Turbine 4: Chained Expression Algebraic Reduction
  Simplifies chained arithmetic (e.g. `acc * 2 / 4` -> `acc / 2`).

Turbine 5: Multi-Accumulator Induction Scaling
  128x step loop induction scaling with automatic remainder cleanup.

Turbine 6: Register Promotion Engine & Invariant Peeling
  Promotes invariant loop variables to CPU registers, eliminating stack RAM writes.

Turbine 7: SCEV Recurrence Attractor Solver
  Proves fixed-point attractor convergence and derives closed-form loop results.
